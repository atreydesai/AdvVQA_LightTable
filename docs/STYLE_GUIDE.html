Light Table

A photographer's light table is where you lay out every frame of a shoot and study how the picture changed from take to take. This interface does the same for questions: their images, their clues, and the model's verdicts — over time.

Draft v0.1 — for review Desktop only (≥ 1280 px) · Light theme, committed

Principles

Apple HIG, applied to a review tool
Content first, chrome recedesThe question's images are the interface. Chrome is white, hairline-separated, and never competes with the photograph being judged. No gradients, no shadows heavier than 1 px of ambiguity.
Time is the primary axisOne scrubber governs the whole question. Every subpart, verdict, and caption answers the same question: "what did this look like at moment t?" Nothing on screen may disagree with the playhead.
Images read truePhotos sit on a neutral gray mat (#F1F1F4), never on pure white or a tinted surface, so edits to brightness, crop, and position are judged accurately.
Desktop densityNo responsive collapse. Panels use fixed, generous proportions tuned for 1280–1920 px. Keyboard is first-class: ←/→ steps revisions, ⇧←/→ jumps milestones, 1–9 selects subparts.
Semantic color is not decorationGreen means the model answered correctly. Red means it didn't. Amber means abstain/draft. These hues appear nowhere else, so a glance at any screen is a truthful summary.
Scrubbing feels physicalDragging the playhead swaps images instantly (like scrubbing film); discrete jumps (clicking a mark, arrow keys) get a 220 ms crossfade. Revisions are prefetched so the slider never stutters.

Timeline mark hues

Each mark on the scrubber is colored by what kind of change it records, so the shape of a question's history is legible before you scrub at all — a cluster of blue means heavy image rework; purple means the writing changed.

Typography

native SF, no webfonts

The tool is desktop-only and its reviewers are on Macs, so the honest HIG choice is the native San Francisco system stack — true SF Pro on macOS, no font download, no fallback drift. Timestamps, revision numbers, and diff text use SF Mono (ui-monospace) with tabular numerals so columns of times align.

The timeline scrubber

live demo — drag the playhead

The signature component. One track for the whole question; marks are actual recorded events (image uploads, clue edits, model runs, milestones) positioned in event order, evenly spaced — not proportional to wall-clock time, since authoring sessions have hour-long gaps that would crush the interesting parts together. Drag through it: all three subparts below re-render to their state at that moment, which is how you review the effect of repositioning across every part at once.

Image revision Clue change Model run Milestone

Placeholder graphics stand in for slot images: watch the dark subject move and the crop tighten as revisions land. The "rev n/m" chip flips to accent-blue on the subpart that changed at the current mark. Arrow keys work when the playhead is focused.

Components

the recurring vocabulary

Subpart tabs

Segmented control per HIG. The dot is the VLM verdict at the current playhead position — it updates as you scrub. Bonus questions group tabs by sub-question.

Verdict badges

✓ Correct · gpt-5.2 ✕ Incorrect · qwen3-vl — Abstained Not yet tested

Always paired with the model name. Quiet backgrounds; the hue itself carries the meaning.

Image mat

Every image on a 10 px mat with a hairline. Aspect ratio is preserved; the mat absorbs the variance so grids stay aligned.

Text diff — first authored vs. final submitted

Word-level highlights inside line-level add/remove rows — git style, SF Mono. A "no changes" state renders the text once on the mat with a quiet "unchanged" chip.

Open design questions

answer any or all — defaults noted
Mark spacing: event-order (default) or true time-proportional?Event-order spacing keeps marks readable; a toggle for proportional could be added later if the real rhythm of a session matters to you.
Should the broad view include the clue text under each image?Default: image-only cards with a one-line clue on hover, to keep 5+ subparts comfortably on screen at 1440 px.
Model-run marks on the timeline: on by default, or a filter toggle?Sessions with heavy testing can log dozens of runs. Default: shown, with a mark-type filter in the toolbar.
Question browser: reuse the review queue's card list, or a denser table?Default: dense sortable table (ID, type, author, status, #revisions, last activity) — this is a lookup tool, not a triage queue.
